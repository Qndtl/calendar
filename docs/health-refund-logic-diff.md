# 건강보험 환급 로직 — 기존 vs 신규(v2) 케이스 상세 비교

## 기준 설정

이 문서의 모든 예시는 **선택월 = 2026년 5월** 기준으로 작성합니다.

| 시간 표기 | 실제 월 |
|---|---|
| 5개월 전 | 2026년 3월 |
| 4개월 전 | 2026년 4월 |
| **3개월 전 (공제 발생 월)** | **2026년 5월** |
| 2개월 전 | 2026년 6월 |
| 1개월 전 | 2026년 7월 |

> **차이 4** (1/30, 1/31 특수 케이스)는 4개월 전이 1월이어야 발생하는 케이스이므로  
> 해당 섹션만 **선택월 = 2026년 2월** 기준으로 별도 작성합니다.

---

## 차이 1 — "5개월 전 있음"과 "4개월 전 초일"이 같은 결과였던 케이스

### 배경

기존 로직에서 아래 두 케이스는 **진입 경로가 달랐지만 결과가 항상 동일**했습니다.

- `5개월 전(3월) 출역 있음` → `refundHandleWithTwoMonthsAgoWork`
- `4개월 전(4월) 초일 출역` → `refundHandleFirstDayWork`

두 함수 모두 내부 로직이 사실상 동일합니다.

```javascript
// 기존 — 두 함수가 동일한 구조
if (currentMonth.length >= 8) → 금액 비교
else → 환급 (공제 있으면)
```

신규는 이 두 케이스를 `period4Count >= 8`로 통합하고, 추가로 `justified` 조건을 요구합니다.

---

### 예시 A — 5개월 전 있음, 4개월 전 8일, 3개월 전 < 8일

| 월 | 출역일 |
|---|---|
| 3월 (5개월 전) | 3/10 |
| 4월 (4개월 전) | 4/5, 4/7, 4/10, 4/12, 4/15, 4/17, 4/20, 4/22 (8일) |
| 5월 (3개월 전) | 5/3, 5/8, 5/12 (3일) |
| 6월 (2개월 전) | 없음 |

**기존 흐름**

```
oneMonthAgo(4월) 있음
  → twoMonthsAgo(3월) 있음
    → refundHandleWithTwoMonthsAgoWork
      → currentMonth(5월) = 3일 < 8
        → 환급
```

**신규 흐름**

```
totalDays = sorted4(8) + sorted3(3) = 11 >= 8

period4Start = 2026-04-05
period4End   = 4/5 + 29일 = 2026-05-04  (4월은 30일이므로 daysInMonth-1 = 29)
period4Count = [4/5 ~ 5/4] 범위 = 4/5~4/22(8일) + 5/3(1일) = 9 >= 8

justified:
  allDates.some(d >= '2026-05-04') → 5/8이 해당 → true

→ Step 5a, 공제 정당 → 금액 비교
```

| | 기존 | 신규 |
|---|---|---|
| **결과** | **환급** | **금액 비교** |

---

### 예시 B — 4개월 전 초일 출역, 4개월 전 8일, 3개월 전 < 8일

| 월 | 출역일 |
|---|---|
| 3월 (5개월 전) | 없음 |
| 4월 (4개월 전) | 4/1, 4/3, 4/5, 4/8, 4/10, 4/12, 4/15, 4/17 **(초일 출역, 8일)** |
| 5월 (3개월 전) | 5/3, 5/8, 5/12 (3일) |
| 6월 (2개월 전) | 없음 |

**기존 흐름**

```
oneMonthAgo(4월) 있음
  → twoMonthsAgo(3월) 없음
    → isFirstDayOfMonth(4/1) = true
      → refundHandleFirstDayWork
        → currentMonth(5월) = 3일 < 8
          → 환급
```

**신규 흐름**

```
period4Start = 2026-04-01
isFirstDayOfMonth(4/1) = true → period4End = 2026-04-30 (4월 말일)
period4Count = [4/1 ~ 4/30] = 8 >= 8

justified:
  allDates.some(d >= '2026-04-30') → 5/3이 해당 → true

→ Step 5a, 공제 정당 → 금액 비교
```

| | 기존 | 신규 |
|---|---|---|
| **결과** | **환급** | **금액 비교** |

> **포인트:** 기존에서 "5개월 전 있음"과 "4개월 전 초일" 두 경로가 모두 "3개월 전 < 8 → 환급"으로 끝났지만,  
> 신규는 `period4Count >= 8 + justified` 조건을 충족하면 금액 비교로 판단이 바뀐다.

## 차이 2 — "4개월 전 출역 >= 8일" 단독 판단 vs period4 + justified

### 배경

기존에서 4개월 전 출역이 8일 이상이면 무조건 금액 비교였습니다.

```javascript
// 기존 existing.js:158
if (oneMonthAgo.length >= 8) {
  // 금액 비교 후 징수 or 환급
  return refunds;
}
```

신규는 `period4Count >= 8`이어도 `justified` 조건을 추가로 확인합니다.  
`justified`의 핵심은 **"period4End(첫 출역+30일) 이후에도 출역이 있는가"** 입니다.

```javascript
// 신규 new.js
const justified = allDates.some(d => d >= period4End)  // 핵심 조건
  || sorted3LastDayWorked
  || twoMonthsAgo.length > 0;
```

---

### 예시 — 4개월 전 8일, 그 이후 출역 없음

| 월 | 출역일 |
|---|---|
| 3월 (5개월 전) | 없음 |
| 4월 (4개월 전) | 4/5, 4/7, 4/10, 4/12, 4/15, 4/17, 4/20, 4/22 **(8일, 초일·특수일 아님)** |
| 5월 (3개월 전) | 없음 |
| 6월 (2개월 전) | 없음 |

**기존 흐름**

```
oneMonthAgo(4월) 있음
  → twoMonthsAgo(3월) 없음
    → isFirstDayOfMonth(4/5) = false
      → isSpecial = false
        → oneMonthAgo.length = 8 >= 8
          → 금액 비교
```

**신규 흐름**

```
totalDays = sorted4(8) + sorted3(0) = 8 >= 8

period4Start = 2026-04-05
period4End   = 4/5 + 29일 = 2026-05-04
period4Count = [4/5 ~ 5/4] = 8 >= 8

justified:
  allDates.some(d >= '2026-05-04') → 5월 출역 없음 → false
  sorted3LastDayWorked             → false (4/5는 1월 특수일 아님)
  twoMonthsAgo(3월).length > 0     → false

justified = false → 환급 (공제 부당)
```

| | 기존 | 신규 |
|---|---|---|
| **결과** | **금액 비교** | **환급 (공제 부당)** |

> **포인트:** 기존은 4개월 전에 8일 이상이면 공제가 정당하다고 봤다.  
> 신규는 "그 이후로도 계속 출역이 있어야" 공제가 정당하다고 본다.  
> 4월에만 8일 일하고 이후 아무 출역이 없으면 신규에서는 공제를 부당으로 판단해 환급한다.

## 차이 3 — 4개월 전 없음 + 3개월 전 일반 날짜 + 2개월 전 출역 있음

### 배경

"4개월 전 없음, 3개월 전 초일 미출역, 일반 날짜 시작" 케이스에서  
기존은 **"3개월 전 첫 출역+30일 이후 출역 여부"** 로 판단합니다.  
신규는 **conditionA — "3개월 전 초일 출역 여부"** 하나로만 판단합니다.

---

### 예시 — 3개월 전 일반 날짜 시작, 8일 이상, 2개월 전에 첫 출역+30일 이후 출역 있음

| 월 | 출역일 |
|---|---|
| 4월 (4개월 전) | 없음 |
| 5월 (3개월 전) | 5/5, 5/7, 5/10, 5/12, 5/15, 5/17, 5/20, 5/22 **(8일, 5/1 초일 아님)** |
| 6월 (2개월 전) | 6/7 (1일) |

**기존 흐름**

```
oneMonthAgo(4월) 없음 → refundHandleNoOneMonthAgoWork
  → isFirstDayOfMonth(5/5) = false
    → isSpecial = false
      → refundHandleCurrentMonthRegularDate
        → currentMonth(5월) >= 8
          → lastFromFirstDate = 5/5 + 30일 = 6/4  (5월은 31일)
            → oneMonthAfter(6월).includes('2026-06-04') → 6/7 ≠ 6/4 → false
              → refundHandleThirtyDaysAfterCheck
                → filtered(> 6/4) = [6/7] → 있음
                  → 금액 비교
```

**신규 흐름**

```
sorted4 = 0 → totalDays = sorted3(8) + sorted2(1) = 9 >= 8

period3Start = 2026-05-05
period3End   = 5/5 + 30일 = 2026-06-04  (5월은 31일이므로 daysInMonth-1 = 30)
period3Count = [5/5 ~ 6/4] = 5/5~5/22(8일), 6/7은 범위 밖 = 8 >= 8
period4Count = 0 → Step 5c

conditionA = isFirstDayOfMonth(5/5, 2026, 5) → false
→ 환급 (공제 부당)
```

| | 기존 | 신규 |
|---|---|---|
| **결과** | **금액 비교** | **환급 (공제 부당)** |

> **포인트:** 기존은 "3개월 전 첫 출역 기준 +30일 이후에도 출역이 있으면 연속 근로로 보고 금액 비교"로 처리했다.  
> 신규는 conditionA — "3개월 전 초일 출역 여부"만 기준이다. 초일에 출역하지 않으면 뒤에 무슨 출역이 있더라도 공제 부당으로 보고 환급한다.

## 차이 4 — 1/30, 1/31 특수 케이스 + 2개월 전 출역 위치

> 이 케이스는 4개월 전이 1월이어야 발생합니다.  
> **선택월 = 2026년 2월** 기준으로 작성합니다.

| 시간 표기 | 실제 월 |
|---|---|
| 4개월 전 | 2026년 1월 |
| **3개월 전 (공제 발생 월)** | **2026년 2월** |
| 2개월 전 | 2026년 3월 |

### 배경

4개월 전 첫 출역이 **1/30 또는 1/31**인 특수 케이스에서,  
period4End가 **3월로 넘어갑니다** (1/30 + 30일 = 3/1, 1/31 + 30일 = 3/2).

이 때문에 기존과 신규에서 "2개월 전 출역이 어느 날짜인가"에 따라 결과가 달라집니다.

---

### 예시 — 4개월 전 1/31 시작, 3개월 전 8일 이상, 2개월 전 3/1 출역

| 월 | 출역일 |
|---|---|
| 1월 (4개월 전) | 1/31 **(1/31 특수일)** |
| 2월 (3개월 전) | 2/3, 2/5, 2/8, 2/11, 2/14, 2/18, 2/21, 2/24 (8일) |
| 3월 (2개월 전) | 3/1 (1일) |

**기존 흐름**

```
oneMonthAgo(1월) 있음
  → twoMonthsAgo(12월) 없음
    → isFirstDayOfMonth(1/31) = false
      → isSpecial = 1/31 → true → refundHandleSpecialDateWork
        → merged = [1/31, 2/3~2/24] = 9일 >= 8
          → lastDayWorked = isLastDayOfMonth(2/24, 2026년 2월) → 2/28 ≠ 2/24 → false
            → oneMonthAfter(3월) = [3/1] 있음
              → 금액 비교
```

**신규 흐름**

```
sorted4 = [1/31]
period4Start = 2026-01-31
1월 daysInMonth = 31 → period4End = 1/31 + 30일 = 2026-03-02

period4Count = [1/31 ~ 3/2] = 1/31, 2/3~2/24(8일), 3/1(1일) = 10 >= 8

justified:
  allDates.some(d >= '2026-03-02') → 3/1 < 3/2 → false  ← 3/1이 3/2 미만이므로 해당 안 됨
  isJanSpecialDate(1/31) = true → sorted3LastDayWorked:
    sorted3(2월)에 2/28 있는가 → 2/24가 마지막 → false
  twoMonthsAgo(12월).length > 0 → false

justified = false → 환급 (공제 부당)
```

| | 기존 | 신규 |
|---|---|---|
| **결과** | **금액 비교** | **환급 (공제 부당)** |

> **포인트:**  
> 기존은 "2개월 전(3월)에 출역이 있으면" 금액 비교로 처리한다.  
> 신규는 period4End가 3/2인데, 2개월 전 출역이 3/1이면 `d >= period4End(3/2)`를 만족하지 못해 공제 부당으로 환급한다.  
> 즉, **3/1 출역이냐 3/2 출역이냐**에 따라 결과가 갈린다.
